# СтегоВизор 2.0

**Автономный комплекс локального анализа файлов и стеганографических рисков для закрытых промышленных контуров.**

Язык: Python 3.9+. Зависимости: numpy, scipy, Pillow, matplotlib, pypdf, customtkinter (GUI; при его отсутствии автоматически используется стандартный Tkinter). Сетевые подключения и браузер для работы не используются.

План разработки и актуальные приоритеты: [ROADMAP.md](ROADMAP.md).

## Назначение

В промышленных системах (АСУ ТП, SCADA, HMI, системы видеоконтроля) изображения передаются между
сегментами сети: снимки технологических камер, тепловизионные кадры, экраны HMI, схемы и мнемосхемы.
PNG хранит данные без потерь, поэтому это удобный контейнер для скрытых каналов: утечки данных,
доставки команд или вредоносной нагрузки. Комплекс решает такие задачи:

1. **Обнаружение скрытых вложений**: структурный и статистический анализ PNG; глубокий статический анализ PDF (объекты, потоки, действия, вложения, изображения, скрытый текст, подписи); статистический анализ поддерживаемых растровых изображений.
2. **Оценка стеганографической стойкости** изображения как контейнера: сколько данных можно скрыть
   незаметно для средств контроля (индекс ИСС, безопасная ёмкость).
3. **Оценка живучести скрытого канала** к преобразованиям. Показывает, какие преобразования гарантированно его уничтожают.
4. **Нейтрализация (санитизация, CDR)**: очистка структуры PNG и пересборка PDF без активного содержимого,
   вложений и метаданных; перезапись LSB без заметного искажения.
5. **Непрерывный контроль каталога** (шлюз приёма файлов) с карантином, журналом SQLite и отчётами.


## Быстрый старт

```bash
python main.py                                   # графический интерфейс
python main.py samples demo --count 3            # испытательный набор с разметкой
python main.py analyze demo -o reports           # анализ каталога + отчёты HTML/JSON/CSV
python main.py analyze incoming/ -r -o reports   # PNG, PDF, JPEG, BMP, TIFF, WEBP, GIF
python main.py analyze secret.pdf --password 'пароль' -o reports
python main.py sanitize incoming/doc.pdf -o clean/doc.pdf
python main.py pdf-extract incoming/doc.pdf -o extracted
python main.py robustness demo/camera_00_clean.png --attacks --report rob.html
python main.py benchmark demo                    # точность на размеченном наборе
```

## Интерфейс

Графический интерфейс оформлен на CustomTkinter в стиле современной веб-панели: тёмная шапка,
карточки сводки, таблица очереди с поиском и фильтрами, карточка результата с метриками и
действиями. Поддерживаются hover-эффекты, масштабирование и адаптивная компоновка под размер окна.
Если пакет `customtkinter` недоступен, автоматически запускается резервный Tkinter-интерфейс с тем же
набором операций, но без современного оформления.

## Поддерживаемые форматы (версия 2.0)

- **PNG/APNG** — структурный разбор и полный имеющийся статистический стегоанализ; санитизация PNG.
- **JPEG, BMP, TIFF, WEBP, GIF** — статистический анализ пиксельного представления через Pillow. Для GIF анализируется кадр, который возвращает декодер Pillow; проверка анимационных кадров отдельно не выполняется. PNG-специфичные проверки к ним не применяются.
- **PDF** — глубокий локальный статический анализ без исполнения содержимого:
  * структура файла: сигнатура, xref/startxref, `%%EOF`, данные после EOF и `endstream`, инкрементальные обновления, неиспользуемые объекты, объектные потоки;
  * обход всех достижимых объектов и потоков; активные конструкции: JavaScript (включая обфускацию), Launch, OpenAction, `/AA`, SubmitForm, ImportData, GoToR/GoToE, RichMedia, 3D, Movie/Sound/Rendition, XFA;
  * вложения и associated files с проверкой сигнатур и расширений; команда `pdf-extract` извлекает их для отдельной проверки;
  * изображения, включая изображения внутри Form XObject и inline, со статистическим стегоанализом в пределах лимитов `pdf.max_images` и `pdf.full_image_analysis`;
  * скрытый текст: невидимый режим `Tr 3`, микроскопический кегль, текст за пределами области страницы, белый текст, пробельные и нулевые символы;
  * метаданные Info и XMP, цифровые подписи и их покрытие, шифрование (пробуется пустой пароль, при необходимости — `--password`).
  Санитизация PDF (CDR) пересобирает документ: удаляет JavaScript и действия, вложения, формы, аннотации, ссылки, подписи, метаданные и неиспользуемые объекты, фильтрует скрытый текст и перекодирует изображения с перезаписью LSB. Результат повторно проверяется встроенным анализатором.

## Автономная эксплуатация

Программа не открывает браузер, не обращается к сайтам и не требует интернет-соединения во время работы. Для закрытого контура поставьте зависимости из заранее подготовленного локального wheelhouse: `pip install --no-index --find-links ./wheelhouse -r requirements.txt`. Само приложение не выполняет сетевых запросов; обновление зависимостей и перенос пакетов выполняются администратором отдельно.

Общие параметры: `-c config.json`, `--log-level`, `--log-file`.

Пароль зашифрованного PDF передаётся только параметром `--password` (в GUI — в поле «Пароль PDF») и используется исключительно для расшифровки при чтении. В конфигурацию, отчёты и журнал он не записывается.

**Коды возврата** (для интеграции со шлюзами, SIEM, CI и сценариями АСУ ТП):
`0` вложений не выявлено, `1` подозрительно, `2` обнаружено вложение, `3` ошибка.

## Методы

**Структурный анализ.** Проверяются сигнатура, порядок и уникальность критических чанков, CRC32 каждого
чанка, корректность IHDR/PLTE (в том числе дубли цветов в палитре как признак EzStego-подобных методов),
неизвестные и частные чанки, размер вспомогательных чанков, содержимое tEXt/zTXt/iTXt (Base64, hex,
высокая энтропия, сигнатуры ZIP/PDF/ELF/PE/сценариев). Поток IDAT распаковывается целиком: данные
после конца zlib-потока, избыток или недостаток относительно размера из IHDR (включая Adam7), недопустимые
типы фильтров строк. Отдельно анализируются данные после IEND. Каждая находка получает критичность
(информация / низкая / средняя / высокая / критическая) с весами 0/10/35/65/90.

**Анализ PDF.** Файл разбирается целиком локально, без открытия внешним приложением и без исполнения
JavaScript, действий и вложений. Проверяются сигнатура и версия, цепочка xref/startxref, маркер `%%EOF`,
данные после EOF и после `endstream`, инкрементальные обновления, объектные потоки, недостижимые объекты
и потоки с несоответствующей длиной. Обход графа объектов выявляет JavaScript (включая признаки обфускации),
Launch, OpenAction, `/AA`, SubmitForm, ImportData, GoToR/GoToE, RichMedia, 3D, Movie/Sound/Rendition и XFA.
Вложения и associated files проверяются по сигнатурам и расширениям. Изображения, включая Form XObject
и inline, декодируются и анализируются статистическими детекторами в пределах лимитов конфигурации.
Скрытый текст определяется по режиму `Tr 3`, микроскопическому кеглю, выходу за область страницы,
белому цвету и пробельным/нулевым символам. Метаданные Info/XMP сопоставляются с находками, проверяются
цифровые подписи и их покрытие. Зашифрованный документ открывается с пустым паролем или `--password`;
пароль не сохраняется. Каждая находка получает критичность, итоговый риск и заключение формируются
общими правилами.

**Санитизация PDF.** Документ пересобирается через `PdfWriter`: в очищенную копию попадают только страницы
и необходимые ресурсы. Удаляются JavaScript, действия, OpenAction, вложения, формы, аннотации, ссылки,
подписи, метаданные, XMP и неиспользуемые объекты; хвостовые данные и старые версии не переносятся.
Скрытые текстовые операторы отбрасываются, изображения декодируются и перекодируются с предсказательной
перезаписью LSB (с сохранением прозрачности), после чего результат повторно анализируется и в отчёт
попадают остаточные находки. Встроенные inline-изображения сохраняются без перекодирования; это
указывается в отчёте. Содержимое PDF при санитизации не исполняется.

**Статистический стегоанализ** по каждому цветовому каналу:
* χ²-атака: p = 1 − F(Σ(h₂ₖ − ēₖ)²/ēₖ), ēₖ = (h₂ₖ + h₂ₖ₊₁)/2. Прогрессивная кривая оценивает длину последовательного вложения.
* RS: доли регулярных/сингулярных групп (маска 0110) для M и −M на исходном изображении и с инвертированными LSB,
  затем квадратное уравнение 2(d₁+d₀)z² + (d₋₀−d₋₁−d₁−3d₀)z + d₀−d₋₀ = 0, p = z/(z−½). Считается по горизонтали и вертикали.
* SPA: ½(|W|+|Z|)p² + (2|X|−|P|)p + |Y|−|X| = 0.
* WS: p = 2 Σ wᵢ (sᵢ − s̄ᵢ)(sᵢ − ĉᵢ), wᵢ ∝ 1/(5+σᵢ²).
* FRN (тест однородных областей, для синтетического контента HMI/SCADA): в чистом изображении окна 3×3 с
  размахом ≤ 2 постоянны. При вложении с долей r доля непостоянных окон f = 1 − (1 − r/2)⁹, откуда r = 2(1 − (1−f)^{1/9}).
  Метод выявляет и **LSB-согласование (±1)**, против которого RS/SPA/WS бессильны.

Оценка доли по каналу: 0.5·WS + 0.25·RS + 0.25·SPA (или FRN, если он применим и больше).
Вероятность обнаружения задаётся логистической функцией с центром между порогами `payload_suspicious`
и `payload_stego`; также учитывается χ²-атака.
Интегральный риск: R = 100·(1 − (1 − Rстат/100)(1 − Rструкт/100)). Заключение по порогам 30/60.

**Оценка стеганографической стойкости.** В центральный фрагмент (до 512×512) встраиваются случайные
сообщения с долями r ∈ {0.5%…100%} методами LSB-замены и LSB-согласования. Для каждого r считаются
P_обн(r) ансамбля «слепых» детекторов, PSNR и SSIM. Результаты:
* безопасная доля r*: максимальное r, при котором P_обн < 0.5 для всех r' ≤ r;
* безопасная ёмкость C* = r*·N/8 байт;
* **ИСС = 100·(1 − AUC)**, где AUC это нормированная площадь под P_обн(log r). Итог берётся по наиболее
  опасному методу. Классы: ≥70 высокая, 40–70 средняя, <40 низкая.

Высокий ИСС значит, что изображение удобно как контейнер (шумные текстурированные кадры камер).
Низкий ИСС типичен для экранов HMI и схем: любое вложение в них заметно.

**Санитизация PNG.** Удаляются все чанки, кроме IHDR/PLTE/IDAT/IEND/tRNS, и данные после IEND.
LSB перезаписываются предсказательно: новый бит выбирается так, чтобы значение было ближе всего к
предсказанию по 4 соседям, вычисленному только по старшим битам. Результат не зависит от исходных LSB,
поэтому канал уничтожается полностью (BER ≈ 0.5), а изображение не вызывает ложных срабатываний
детекторов (в отличие от случайной замены LSB). PSNR ≈ 51 дБ.

## Результаты испытаний (синтетический набор, `samples --count 5 --seed 11`, 97 файлов)

| Класс | Верно |
|---|---|
| Чистые контейнеры (камера, тепловизор, HMI, схема) | 20/20 (FPR 0%) |
| LSB-замена 10% / 40% / 100% | 45/45 |
| LSB-согласование 40% | 5/15 (выявляется на HMI, на шумных кадрах нет) |
| Данные после IEND, zTXt, частные чанки, данные после zlib-потока | 17/17 |

Accuracy 89.7%, Precision 100%, TPR 87%. Для LSB-замены граница уверенного обнаружения около 10% заполнения,
до ~5% вложение статистически незаметно. Это и отражает ИСС.

## Ограничения

- PDF анализируется статически и полностью локально: выполняется обход объектов, потоков, вложений, изображений и скрытого текста, но документ не исполняется и не эмулируется. Это не антивирус и не песочница; эвристики могут давать ложные срабатывания (например, `/URI`, `/OpenAction` или цифровая подпись сами по себе не доказывают вредоносность).
- При санитизации PDF inline-изображения в потоках содержимого не перекодируются; изображения в обычных и Form XObject перекодируются. Нестандартные фильтры и повреждённые документы могут переноситься частично — остаточные находки показываются в отчёте.
- Для зашифрованного PDF без корректного пароля доступен только ограниченный анализ; пароль задаётся параметром `--password` или в поле GUI и не сохраняется.
- Для JPEG/BMP/TIFF/WEBP/GIF используются статистические методы по декодированным пикселям; специфические структурные проверки и санитизация для этих форматов не реализованы.
- Программа не открывает документы внешними приложениями автоматически и не запускает содержимое проверяемых файлов.

* LSB-согласование (±1) в шумных естественных изображениях слепыми методами практически не обнаруживается.
  Комплекс честно отражает это в оценке стойкости (ИСС LSB-согласования ≈ 99) и рекомендует санитизацию как
  гарантированную меру.
* Адаптивные методы (HUGO, WOW, S-UNIWARD) требуют стегоанализа на машинном обучении (SRM + ансамбль
  классификаторов) и в текущую версию не входят. Санитизация уничтожает и их.
* Для палитровых изображений статистический анализ ведётся по индексам палитры, достоверность ниже.
* После санитизации изображения со вложением ±1 в однородных областях следы модификации остаются видимыми
  (сам канал при этом уничтожен).

## Конфигурация

`python main.py init-config config.json` сохраняет параметры по умолчанию (пороги, доли и число
испытаний для оценки стойкости, максимальный размер анализируемого фрагмента, путь к журналу).
Лимиты приёма файлов: `max_file_size_mb`, `max_decompressed_mb`, `max_image_pixels`;
резерв под будущий разбор архивов: `max_archive_depth`, `max_nested_files`.
Секция `pdf` задаёт лимиты разбора (`max_objects`, `max_stream_bytes`, `max_attachments`, `max_pages`,
`max_images`, `full_image_analysis`, `max_text_chars`) и параметры санитизации
(`sanitize_reencode_images`, `sanitize_remove_hidden_text`).
Пример: `config.example.json`.
